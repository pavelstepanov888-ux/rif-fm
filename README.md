# Риф FM — главная страница

Локальный прототип актуальной главной из Figma. React, TypeScript и Vite; обычный CSS и переменные дизайн-системы.

## Запуск

```sh
cd rif-fm
npm install
npm run dev
```

Открыть http://127.0.0.1:5173. Проверка сборки: `npm run build`.

## Компоненты и поведение

- `src/components/ui.tsx`: Button с вариантами Primary/Secondary/Tertiary, Select, Icon, Avatar, Hosts, Heading, LiveLabel, PlayerWave, Volume, Dialog.
- `src/components/player.tsx`: NowPlaying, ButtonListen, общий RadioProvider, закреплённый Player, VideoPlayer и полноэкранная трансляция.
- `src/components/playlist.tsx`: полноэкранная история эфира; `src/playlist-data.ts`: данные макета; `src/playlist.css`: стили нового блока и плейлиста.
- `src/components/mobile-bar.tsx` и `src/mobile-bar.css`: Mobile Bar, Tab Bar и Mini Player по исходным компонентам. Для мини-плеера используется локальный Inter (SIL OFL, лицензия рядом с файлом шрифта); табы — Helvetica Neue 11/14.
- `src/App.tsx`: Header, Hero, ProgramCard, PageSection, ContactCard, Socials, Footer и MobileBar.
- Состояние воспроизведения и громкость общие для кнопки в hero, нижнего плеера и кнопки эфира в плейлисте. В NowPlaying отображаются обложка 48×48, подпись, исполнитель/трек и кнопка истории эфира. На мобильной главной Mini Player и табы всегда закреплены снизу, включая первый экран с hero, в обеих версиях оформления.
- У табов нет общей плашки и фона выбранного пункта: активный текст/иконка красные, остальные используют `Text/Accent Secondary` и `Icon/Accent Secondary` (`#3B8DCF` в версии 1, `#1980D4` в версии 2). Четыре пункта равной ширины, иконки в контейнере 24, подписи 11/14, gap 4, отступы 8 сверху/снизу. Общая подложка Mobile Bar — градиент. Боковые отступы 12 px, нижний — не менее 12 px с учётом safe area, между мини-плеером и табами 8 px. Мини-плеер остаётся стеклянной карточкой, с плоскими иконками play/pause и видео, а также добавленным входом в плейлист.
- Фиксированный контейнер нижней панели использует `100dvh` при обычном масштабе и совпадении видимой области с областью раскладки. При зуме, расхождении размеров или отсутствии поддержки `dvh` размеры и смещения берутся из `VisualViewport`. Горизонтальное переполнение страницы ограничено; карточки листаются внутри собственной ленты. Модальные окна блокируют прокрутку и body, и корневого элемента.
- Видимая подпись кнопки в hero всегда «Слушать эфир»; состояние воспроизведения отражает иконка. Иконки Secondary используют `Icons/Secondary`, ховер табов — `Text/Accent` без фоновой плашки.
- В экране трансляции на самом видео остаются плашка эфира и центральная кнопка Play; прогресс программы расположен под видео. Видео и информация растягиваются до общей высоты, как в макете: при контейнере 1344 px видео занимает 764×494 px, вся колонка — 530 px. Сетка центрируется по вертикали в области под верхней панелью; короткие и мобильные экраны допускают прокрутку.
- Состояния Hover применяются только на устройствах с указателем, Focus — через `:focus-visible`. Учитывается `prefers-reduced-motion`. Модальные окна удерживают фокус, закрываются Escape и возвращают фокус инициатору.
- Иконки плейлиста в hero и обоих закреплённых плеерах открывают один экран «Что звучало». В десктопном плеере иконка расположена крайней справа после «Смотреть трансляцию», отступ 16 px, видимый размер 24×24 и расширенная область нажатия 44×44.
- Над историей — два нативных селекта в стиле Secondary 48 px: день и время («Весь день» плюс шесть четырёхчасовых интервалов 00:00–04:00 … 20:00–24:00). Фильтры применяются вместе, список сбрасывает прокрутку; для пустого результата есть возврат к сегодняшнему эфиру. На мобильном большая карточка текущего трека скрыта целиком, остаются фильтры и список.
- Плейлист и видеорежим используют общее появление с плавным подъёмом и затуханием, мягким появлением контента и более коротким сворачиванием. Закрытие по кнопке и Escape дожидается выхода, затем возвращает фокус инициатору и восстанавливает прокрутку страницы. Для `prefers-reduced-motion` движение отключено. Нажатие на свободный фон плейлиста его не закрывает.

## Данные прототипа

Тексты, программа, трек, время карточек и контактные данные взяты из макета. Повторяющиеся заголовки «Письмо редакции» и интервалы «16:00 – 17:30» сохранены из исходного фрейма. По описанию Socials MAX показывается только в футере.

Плейлист использует пример из Figma: 15 октября («Сегодня»), треки и повторяющиеся строки Bryan Ferry сохранены для проверки списка с прокруткой. Это демонстрационная дата, не текущий день. Все треки примера относятся к 15-му часу и попадают в 12:00–16:00. Другие дни и интервалы показывают пустую историю с возвратом к сегодняшней подборке. API истории и воспроизведение архивных треков не подключены; Play рядом с большой обложкой на desktop управляет общим прямым эфиром. Обложки экспортированы из Figma как исходные JPEG 600×600; одна и та же обложка Sade используется в hero, списке и большой карточке.

Ссылки на остальные страницы представлены локальными окнами для проверки переходов. Это не реализация отдельных страниц расписания, документов или рекламодателей.

Аудио- и видеопотоки, а также точные URL соцсетей не заданы в макете. Без них аудиокнопки демонстрируют состояния с уведомлением, видео показывает постер, соцсети сообщают об отсутствии ссылки. Для подключения скопировать `.env.example` в `.env.local` и заполнить нужные значения. Никакой сторонний поток или случайный аккаунт не подставляется.

## Две версии оформления

Версии открываются по отдельным URL: `?version=1` и `?version=2`, добавленным к адресу главной. Например, локально: `http://127.0.0.1:5173/?version=1` и `http://127.0.0.1:5173/?version=2`. Переключателя в интерфейсе нет. Без параметра или при неизвестном значении открывается версия 1. Выбор определяется только URL; прежнее значение localStorage не влияет, адрес и его hash не переписываются.

- Версия 1 сохраняет исходные цвета и декоративные подчёркивания.
- Версия 2: `Text/Secondary` и `Icons/Secondary` — `#547FA2`; `Text/Accent Secondary` и `Icon/Accent Secondary` — `#1980D4`. Акцентные роли используются у Secondary/Tertiary, селектов, иконки и ползунка громкости, кнопок соцсетей в футере. Интерактивные состояния кнопок сохранены.
- Слоган «На волне моего сердца / 95,2 fm» во второй версии использует `Text/Secondary` (`#547FA2`).
- Во второй версии скрыты все декоративные оранжевые подчёркивания компонента Heading, в том числе в видеорежиме. Фирменная графика не меняется.

В обеих версиях на desktop (от 768 px) между блоком «Сейчас играет» и группой кнопок эфира — ровно 40 px. Мобильный отступ сохранён.

Названия новых ролей и переопределения версий хранятся в `design/prototype-tokens.json`. `npm run tokens` генерирует их вместе с исходными переменными в `src/tokens.css`; экспорт `design/figma-tokens.json` сохранён без изменений. Переопределения применяются на корневом элементе документа, поэтому выбранное оформление распространяется и на модальные экраны. Переключателей в интерфейсе нет.

## GitHub Pages

Для GitHub публикуется содержимое этой папки как отдельный репозиторий `rif-fm`. Для изоляции от существующего Git-репозитория проекта рекомендуемая папка копии для публикации — `~/Documents/rif-fm-pages`, вне исходной папки `Rif FM`. В неё копируются исходники сайта с исключением `.git`, `.vercel`, `.env*` (кроме `.env.example`), `node_modules`, `dist`, `dist-pages` и `*.tsbuildinfo`. Новый Git-репозиторий создаётся уже в этой отдельной копии. Файл `.github/workflows/pages.yml` автоматически собирает и публикует сайт при push в `main`; также доступен ручной запуск из Actions.

Настройка репозитория: **Settings → Pages → Source: GitHub Actions**. Сборка использует `npm ci`, Node.js 24 и `npm run build`. Деплой загружает только `dist`.

Workflow получает путь страницы от GitHub и передаёт его в Vite как `VITE_BASE_PATH`. Это поддерживает адреса вида `https://USERNAME.github.io/rif-fm/`, корневой сайт и свой домен. Изображения, SVG-иконки, постер видео, favicon и шрифты используют соответствующий путь. Для локальной проверки варианта с подпапкой:

```sh
VITE_BASE_PATH=/rif-fm/ npm run build -- --outDir dist-pages
```

Потоки и ссылки при необходимости задаются в **Settings → Secrets and variables → Actions → Variables** переменными из `.env.example`. Значения `VITE_*` включаются в клиентскую сборку и должны быть публичными.

Первоначальная публикация из отдельной копии через GitHub CLI после входа в нужный аккаунт. Чтобы сохранить текущую глобальную настройку авторизации Git, не запускать `gh auth setup-git`; при входе через `gh auth login` ответить No на предложение настроить авторизацию Git. Следующие две команды `git config --local` задают авторизацию через gh только для нового репозитория сайта:

```sh
git init -b main
git config --local --replace-all credential.https://github.com.helper ''
git config --local --add credential.https://github.com.helper '!gh auth git-credential'
git add .
git commit -m "Publish Rif FM homepage"
gh repo create rif-fm --public --source=. --remote=origin --push
gh api --method POST 'repos/{owner}/{repo}/pages' -f build_type=workflow
gh workflow run pages.yml
```

Последующие обновления: `git add .`, `git commit -m "Update homepage"`, `git push`.

## Vercel

При публикации текущей папки через CLI указать Framework Preset: Vite, Build Command: `npm run build`, Output Directory: `dist`. При импорте отдельного репозитория сайта Root Directory — `./`. Путь `VITE_BASE_PATH` по умолчанию `/`, поэтому существующее размещение на Vercel продолжает работать. В переменные окружения добавить потоки и ссылки при наличии.
